A

先明确可信代码前提

V1 使用团队审查维护的普通 Python

Recipe 使用分支、循环、分页和共享 helper。 不执行未经审查的 Agent 代码，不接受外部任意 Python。 不建设沙箱、可信 Fetcher、RPC 或自定义 Download Handler。

保留的业务能力 删除或推迟的机制
Source、Python Recipe、YAML 参数、CLI DSL、管理服务、Agent 执行接口
不可变版本、独立 Binding 与 Activation 自动晋升、审批工作流平台
Trial、Gold Fixtures、人工核对 Evaluation 平台、自动评分
原文、观察、修订、Replay、JSON 网络取证、签名收据、冻结响应缓存

Scrapy 设置不能阻止恶意 Python 绕网或修改同权限存储。 哈希用于去重和损坏检查，不提供防篡改证明。 普通子进程管理生命周期，不是安全隔离。 未来开放不可信代码时，必须另行设计可信执行边界。

B

完整架构与模块职责

图中业务组件是同一应用的模块，不是独立服务。 默认单机、一个生产 Crawl 执行槽，本地目录保存原文。 不要求容器、Redis、对象存储产品或第二套工作流引擎。

唯一负责者 负责什么 不重复建设什么
Scrapy 请求调度、去重、下载、重试、跳转、Cookie、解压 PostgreSQL URL Frontier、自写 HTTP 客户端
Procrastinate 持久 Crawl、周期、执行锁、有限任务重跑 自研领取队列、DBOS 叠加
SEAL 归档、业务版本、校验、审核、发布与撤回 独立治理服务、复杂执行协议
C

归档必须放在正确位置

响应中间件按优先级从高到低执行。 将原生 HttpCompression 从 590 调到 610，Archive 设为 605。 其后为 Redirect 600、MetaRefresh 580、Retry 550。 Cookie 若启用仍位于 700；实际完整顺序由 M0 验证。

  • HTML/PDF 均保存 Response.body，不保存提取正文冒充原文。
  • 保存每跳状态、URL、最终 URL、时间、哈希和 Run ID。
  • 重试错误页和跳转响应先归档，网络异常只记失败诊断。
  • 不存传输层字节，不将压缩前长度当成归档长度。
  • 不保存 Cookie、Token 或认证头；敏感 body 拒绝准入。
缓存、观察与 Replay 必须分开

生产与在线 Trial 默认关闭 HTTP 缓存，不主动条件 GET。 M0 验证缓存 500、304 重验证和错误回退。 缓存复用不能冒充新的网络观察或新鲜度证明。 Replay 只查历史输入，缺失即失败，不联网补齐。

共享版本，不共享启用资格

RecipePackage：Python与helper
  • 不可变RecipeVersion：代码与依赖环境
    • Binding A：来源快照与参数A
      • Review A → Activation A
    • Binding B：来源快照与参数B
      • Review B → Activation B

代码、helper、参数、依赖、执行环境与校验版本都影响验证资格。 A 升级不能原位替换 B 的代码或运行环境。 九类业务表保存 Source、RecipeVersion、Binding、Decision、Run、Observation、Document、Revision 和 Result。 原文、报告、代码包与输入清单使用内容寻址工件。

发生什么 应保存什么 不应该发生什么
再次获取相同正文 新 Observation，复用 body 丢失获取历史或新增内容修订
正文 A → B → A 三次 Revision，共用两份 body 按哈希合并掉返回 A 的历史
同原文换 Recipe 新 ProcessingResult 伪造来源内容变化
相同输入与处理键重跑 同输出复用 Result 不同输出最后写入覆盖
Recipe 回滚 新 Activation generation 删除历史或自动撤回错误结果
E

正常自动发布，变更人工审核

首次接入、升级和异常修复需要人工核对。 正常周期无需逐次人工确认。 没有独立预期文档集合时，覆盖率保持 unknown。 HTTP 200、Schema 合格、样本正确都不证明全站完整。 错误结果用独立 withdraw 撤回，下游须消费撤回信息。

F

失败后如何恢复

有界整次重跑，不恢复 Python 执行栈

Procrastinate 管任务重跑，Scrapy 管请求重试。 重跑从固定种子开始，真实重发产生新 Observation。 复用相同 body 和合格 Result，不伪造获取历史。 JOBDIR 不作为任意崩溃恢复保证。

场景 行为
Worker/Spider 退出 有限重跑或 needs_repair；显式配置 stalled 恢复
归档成功，解析失败 保留原文，修复后 Replay 与 Trial
暂存成功，发布失败 完整输入仍有效时重入发布事务
发布后回报前崩溃 幂等完成决议，避免重复发布
旧任务晚到 检查 attempt epoch、generation、run_seq 与最新修订
运行中启用新版 旧 Run 不混用新参数，也不能更新当前指针

执行锁降低重叠，数据库提交校验处理旧进程仍活着的情况。 暂停阻断提交并请求取消，但不能撤回已发网络请求。 不新增 URL Frontier、租约系统或另一套下载缓存。

阶段 用户可观察的关键结果
M0 callback 前原文已存；归档失败零发布；离线 Replay 正确且零请求

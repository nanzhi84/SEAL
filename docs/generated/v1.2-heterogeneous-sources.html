2. 冻结的 Record 与定位合同

type=record 包含 record_type、record_key、schema_version、类型化 JSON data、 可空 detail_url、每个 data 字段的 locator、key_locator、主 snapshot/observation、 补充输入，以及非 URL 业务键需要的 frozen_parent_request={url,role,method:GET}。 JSON 有展示 detail_url 时仍冻结父 API；旧行仅从已接受的原文输入恢复唯一父请求。 身份为 (source_id, namespace, record_type, record_key)；禁止列表下标或位置哈希作为键。 URL 键必须与实际归档响应及详情 URL 一致；JSON 整数键仅允许显式 key_string 转换。

一个响应可输出 0..N Record；一 Record 可引用多个输入，同一 snapshot 可被多个 Record 共享。每字段值必须从已归档输入复算，不接纳脱离原文的替代值。 JSON Pointer 保持数字、布尔、null、数组及对象类型，严格区别 false/0 和整数/浮点数， 拒绝非法转义、负数组下标、NaN/Infinity 和过深 JSON；旧字符串 locator 不变。 record.v1 是技术 JSON 合同，schema_version 为来源输出版本标识，不意味着业务准确性审核。

内容指纹只取 Record 类型、Schema 版本和有效 data；输入、页码、locator 位置、抓取时间 不进入业务指纹。列表重排只改变原文/定位证据，不改变各业务版本。 同一 Binding 的有效基线负责内容变化归因；换 Binding 的不同输出记为 reprocessed， 不能由新结果推断来源更新。原文 bytes hash 与业务内容变化分别记录。

stage 只写不可变处理结果与 emission；完成事务按键聚合。同键同内容去重并合并所有 输入血缘；同键异内容保留候选，整个键排除有效输出并使本轮 partial。 只有最终 complete 的完成事务推进 Record 当前指针；失败或 partial 不覆盖此前成功视图。 未观察旧 Record 一律 unknown，不自动删除，包括本轮零结果或声明范围不完整的情况。 写入继续遵守 Source → Run → Record 锁顺序及 generation/run_seq/attempt fencing。

实现前失败方式与验收要求：

  • JSON 返回稳定 id 与 detailUrl：两轮 collect、Recheck 和 Replay 始终保留同一个业务键/Record ID；没有详情到业务键映射时复查冻结父 API 请求，不能产生 URL 键替代记录。历史配置和已接受行也不能静默改变身份。

  • 排队、失败、重试与并发：调度不提前推迟业务 next_check；仅成功完成事务推进已观察范围。失败保留有界的重试机会；同一 Source 的待执行任务不重复领取，旧 generation/attempt 不覆盖新计划或当前指针。
  • 1000 条 Record、每条 10 个类型化字段：真实采集及原文复算保持完整值和键，并产出可重复性能数据；JSON Pointer 不随字段数重复解析完整大响应。重复 JSON 键、非法 Pointer、false/0、1/1.0、非有限数、补充输入混淆及摘要损坏继续拒绝。

  • recheck.py 单独负责目标计划、父请求证明、未观察范围与完成日期；runs 冻结计划，queue 在 Source 锁下按默认 Binding 的输出合同选择到期 Record/Document，completion 事务提交时推进日期。采集、领域验证和存储职责仍分离。

  • 自动调度按到期时间/身份排序，以不同 GET 请求为预算单位；相同父 API 的到期目标合并。Run 保存 recheck_plan；未计划项不计缺失，API 额外返回的有效记录不提前推进检查日期。手动 --recheck 保持即刻复查全部已知范围，超预算返回 recheck_budget_exceeded，不创建 Run、不改日期。
  • 排队和失败不推进业务 next_check。仅 complete 中已观察的计划目标推进；未观察目标仍 unknown，并获得独立重试退避。失败退避从 30 秒指数增加、上限 1 小时；恢复清零。Source generation/run_seq/attempt fencing、待执行去重与单源 savepoint 保持有效，一个来源缺父请求不会阻塞其他来源。

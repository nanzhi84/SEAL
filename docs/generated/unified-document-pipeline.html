持续发现与恢复

发现

每轮重新访问 Source 入口，Crawl4AI 递归发现链接。永久 Resource 清单保留，新轮 visited 重建。

恢复

恢复当前轮 checkpoint。Source 始终只有一个逻辑 Frontier，首版只允许一个活动执行者。

复查

批量获取到期 Resource，不依赖旧资源仍在导航中。SEAL 保存检查时间，长期 Frontier 与当前轮 SDK checkpoint 分离。

robots 采用 Protego 最长 Allow/Disallow 匹配，政策与业务请求使用同一 Source 身份；403 政策仍拒绝。SDK 错误分类排除源码上下文。归档成功后提交引用，run/URL 重复交付幂等。Source 会话锁和 epoch/generation 保护版本。SDK 0.9.4 checkpoint 会遗漏当前层未交付 URL；SEAL 把这些 URL 补回 SDK pending，崩溃允许重复网络请求，提交不重复。

实施与验收

运行代码已改为 Crawl4AI 单一执行链：HTTP 获取阶段保存正文 bytes；动态页面明确以 rendered_dom 归档，Chromium Fetch 在发网前逐跳拦截越界。HTML/TXT 与文本 PDF 使用 SDK scraper，Office/JSON/图片/专用表单未接替，旧 Recipe YAML 明确拒绝，不能沿用旧九格式支持声明。

核心变更由 fresh 子 agent 在 tests/ 独立端到端验收；隔离数据放 work/、证据放 artifacts/。已验证来源隔离、递归、响应不变/变化/A→B→A、失败重试、原文与结果持久化、TTY/取消、前台及Worker崩溃恢复与旧任务栅栏。CI 仅静态检查，有界样本不证明全站完整。

原文与结果

Observation 的 archive_ref=body_hash；CAS 字节可复算。Version 的 result 保存 SDK CrawlResult，二进制与下载文件以 CAS 外置；新进程可重建。Run.report.crawl_results 按 Observation ID 保存本轮成功、失败及 unchanged 的 SDK 结果 CAS，同事务关联；policy 无 SDK 结果，失败不推进 Version。异常 SDK 字段缺失时联查 Observation 原文与状态；二进制外置后经 Pydantic JSON 编码，PDF 日期保存为 ISO 字符串。

直接 SQL 消费

seal.current_resource_version 按 Source/URL 查当前版本；seal.version 查 timeline；seal.version_delta 按稳定 cursor 取增量。失败观察不进入内容增量。

Run 无错误不表示全站完整；孤立页、表单分页、受阻、预算和范围外内容仍可能遗漏。完全 fresh 子 agent 的最终端到端427项通过，固定旧版本迁移补验另22项通过；核心采集、真实Worker恢复、DOM及旧库备份还原均有有界证据。主agent执行项目Ruff/seiso/打包，GitHub Actions执行CI静态检查。

统一主链：从来源到文件包

按 01 → 08 执行；API 与导出共用读取边界。
  1. 01 / PLAN

    冻结来源与运行

    Adapter、稳定身份、解析合同与预算；生成请求和文档目标。

  2. 02 / ACQUIRE

    受控 Acquisition

    HTTP 或 DOM 获取；执行范围、robots、限流、取消和请求预算。

  3. 03 / ARCHIVE

    原文进入 CAS

    完整字节归档并读回校验，再提交数据库获取事实。

  4. 04 / PARSE

    组装文档输入

    0..N 个候选；真实定位、输入角色与后续任务全部可追溯。

  5. 05 / NORMALIZE

    统一文档与 Markdown

    seal.document.v1；冻结正文与转换合同，计算具名指纹。

  6. 06 / COMMIT

    不可变内容提交

    事务与 attempt fence 保护 Observation、Version 及当前指针。

  7. 07 / SNAPSHOT

    封存固定版本

    冻结来源、Resource → Version 及覆盖描述，校验引用闭包。

  8. 08 / EXPORT

    独立导出与本地核验

    只读指定 Snapshot；完成所有文件与关系校验后原子交付。

Acquisition 管获取，文档目标管交付

一次受控的外部原始数据获取动作

绝大多数对应 HTTP 请求。同 URL 两次实际获取保留两条事实；同字节复用 CAS。DOM 保存实际渲染输入，并明确区别于 HTTP 响应字节。

planned → running → archived / failed / cancelled / abandoned

archived 表示原文完整、哈希已校验且数据库引用已提交；HTTP 错误页归档不代表解析成功。终态不可原位修改，重试产生新动作。

分别确认三个完成点

  1. 原文已归档。
  2. 本页产生的请求及文档目标已持久登记。
  3. 各文档已形成成功或明确失败交付。

分页水位在后续工作可恢复后推进。批量提交一半退出，接管读取原文并补齐余下目标；失效 attempt 不能写入。

查看恢复边界

请求队列和文档目标分别持久管理；checkpoint 保存有界水位、活动引用及带版本 adapter_state。重复获取证据追加关联，不修改已提交 Observation、inputs_ref 或 Version。

四个核心合同，一套读取解释

合同固定内容保证
Resourcefrontier_id + namespace + external_key；public_url 可空，重检有独立 locator。身份不依赖标题、文件名或展示 URL。
seal.inputs.v1真实 acquisition_id、archive_ref、角色、定位、解码与基地址等解析上下文。一输入多文档、多输入一文档均可复算。
seal.document.v1元数据、具名日期、非空 content.markdown、类型化文件与 lineage；原输出格式与转换合同明确。所有新结果唯一格式；纯文本诚实转 Markdown，导出不再解析。
seal.delivery.v1固定 Snapshot、来源范围、覆盖摘要、导出版本、载荷路径、字节数和 SHA-256。文件包可搬移、可断网校验、可重复生成。
查看版本与幂等语义

version_fingerprint = digest(input_fingerprint + parser_fingerprint)，实际计算使用带算法版本的具名 canonical JSON。文档切片、相关外层字段、输入角色、顺序与有效解析参数都参与身份。与当前 Version 比较，A→B→A 保留三次演进。

content_hash 比较规范业务内容；共享批量原件的全量哈希和定位属于血缘，不能让无变化的单篇文档误升版。同输入同解析器却异业务输出属于冲突。同轮规范交付保持幂等，后续获取证据追加记录，禁止原地合并已提交输入清单。

文件交付：一个工作簿连接全部正文和原件

固定目录

delivery/
├── metadata.xlsx
├── markdown/
│   └── <resource_id>/<version_id>.md
├── originals/
│   └── <sha256>.<ext>
└── manifest.json

相对路径、稳定 ID 与哈希命名。Snapshot 封存后可直接导出，无需先 publish；导出不会改变 API 发布指针。

工作簿两张表

documents：一个 Resource / Version 一行，包含来源与文档身份、标题、类型、语言、机构、具名日期、URL、Markdown 路径及摘要、原件数与交付状态。

files：一个文档与原文件关系一行，包含角色、原文件名、包内路径、媒体类型、字节数、SHA-256、来源地址及真实定位。

同一批量 JSON/XML 可供多篇文档共享；一篇文档可关联多个 PDF 和附表。原件不重复保存，文档关系与定位不丢失。

内容完整

每条成功记录恰有一个非空 Markdown，至少关联一份正文原件或 source_response；必需附件全部取得。派生文件不能冒充原件。

结果可复现

正文在 Version 中固定。导出器冻结版本、排序和工作簿时间属性，同快照同范围同运行时得到相同载荷。

完成有证据

暂存生成 → 打开工作簿对账 → 校验全部文件 → 写 manifest → 原子交付。缺件或取消不产生完整目录。

查看 manifest 和范围边界

manifest 列出工作簿、Markdown 与原件的路径、大小及哈希；自身哈希在外部回执，避免循环。覆盖摘要随 Snapshot 冻结，未知分母标 UNKNOWN。文件包完成不能代表全来源覆盖。工作簿容量超限明确失败，禁止截断或增加第二份 Excel。

同步切换新链路，再接入异构来源

本地开发直接采用新合同，不设计历史回填与双格式兼容。schema、写入、公开投影和读取查询必须属于同一个可运行切换单元。

验收面向最终可见结果

对应与完整性

  • Excel 行、Markdown、原件、文件关系与 manifest 全量对账。
  • 无 URL、同名、多附件、共享响应与不同来源相同编号均可区分。
  • HTML/TXT、原生 PDF、OCR PDF 与批量 JSON/XML 均保持来源诚实。
  • 搬移包并断网，路径仍有效，字节与哈希一致。

状态与故障行为

  • 批量提交一半退出，接管后补齐，失效 attempt 无法继续写入。
  • 列表重排不制造版本；真实输入变化与非确定性输出可检出。
  • 导出 A 时采集或发布 B，A 的内容与原件保持固定。
  • 缺件、损坏、取消、超限不生成完整交付目录。

实现阶段由 fresh 子 agent 先定义失败边界，再独立执行真实 CLI 端到端验收；证据包含命令、环境前提、断言、SQL/CAS 对账、源码及测试哈希、交付包和验证回执。当前业务验收尚未运行。

Run 统一失败终态

派生自 Plan · Issue #7

状态只描述执行

pendingrunningfinishingcompletefailedretryable → running

具体原因读取 errors 错误码数组。无重复 termination / terminal_reason；Scrapy finish_reason 保留原始执行上下文。complete 不代表全量覆盖或业务质量通过。

一次失败的边界

  • 临时故障在次数与总期限内 retryable；耗尽后 failed，具体耗尽码进入 errors 与未知覆盖证据。
  • 单次采集时间预算耗尽使用 crawl_time_budget_exceeded；保留原生 finish_reason，合法结果仍可显式导出。
  • generation / run_seq / attempt_epoch 继续隔离旧写入。
  • 只有 complete 推进成功基线；failed 有效产物可显式 export --run。
  • 默认成功视图保留历史成功结果；每条导出验证归档可读性与输入血缘。

历史迁移

0007 将 partial / superseded 改为 failed，历史 terminal_reason 并入 errors，数据库禁止旧终态。归档字节不改：历史 Manifest 可能保留旧词汇。新代码查询当前状态；历史 Manifest 留存当时事实。旧 Recipe 重新 pack，不绕过 environment_drift。

真实 CLI 验收

复用隔离 PostgreSQL、loopback、私有 Archive 的 M3 / Record / Persistence 路径，覆盖解析、恢复、重试耗尽、期限、旧写入、成功视图与显式导出。命令、前提与工件合同见 Plan；最终结果待执行填入。

# ADR-0001：固定采集内核与声明式 Recipe

- 日期：2026-10-08
- 状态：已被 [ADR-0002](0002-python-recipes-minimal-v1.md) 取代；本记录原为未实施提案
- 范围：SEAL 第一版信息采集骨架的历史设计

以下保留原方案的背景与取舍，不再作为现行约束。声明式 Recipe、算子目录、自研任务执行及面向未来 Agent 的安全假设均由修订后的 ADR-0002 替代。现行 V1 是团队维护的可信 Python + Scrapy 原生下载；保留 CLI、应用层原文归档、独立审核和固定发布门禁，但不提供强制网络隔离、恶意代码防护或防篡改原文保证。下文关于未来 Agent、权限和执行边界的表述仅为历史方案，不能用作当前实现要求。

## 背景

系统需要处理异构信息源并输出可追溯的结构化数据。长期目标包含自动适配新来源，但第一版不建设 Agent Harness。后续自动适配的可写范围应限于 Recipe，不能覆盖程序、安全边界或质量标准。

新来源通常缺乏独立真值。仅验证 JSON 结构或观察程序执行完成，不能证明没有漏采、正文完整或元数据正确。因此，策略配置的生命周期与数据质量审核需要先存在，不能等自动化接入后再补。

## 决策

采用固定工作流和有限声明式 Recipe，以人工提案、独立审核和显式启用完成第一版。当时的合同位于设计计划；该文件现已改为 [Python Code Recipe 方案](../plans/v1-information-pipeline.md#4-python-recipe配置与关键接口)，不再描述本历史方案。

执行内核负责可靠状态转移与预置能力；来源配置、安全政策、质量政策、业务 Schema 和真值不属于 Recipe。未来 Agent 替代候选提案者，而不是成为生产工作流的控制中心。

部署采用模块化单体，CLI 与 Worker 共用领域合同与应用服务。来源和 Recipe 以 `.yml` 文件维护，不建设管理页或管理 HTTP API；审核也通过文件与命令行完成。工作目录是配置编辑入口，数据库保存不可变的已应用快照和运行状态，避免文件编辑直接影响在途任务。队列状态使用关系型数据库，大型工件使用对象存储。

## 备选方案与取舍

| 方案 | 好处 | 未选用的原因 |
| --- | --- | --- |
| 管理页与管理 HTTP API | 提供可视化编辑与操作 | 首版操作者可以直接维护 YAML；页面、接口和登录系统增加无必要的开发与运维成本 |
| 每来源独立 Python/JS 适配器 | 表达能力强，初始编写直接 | 不适合作为未来仅允许 Agent 修改的数据边界；审核与沙箱成本高 |
| 先实现自由 Agent 工具循环 | 未知来源探索灵活 | 本阶段目标是可靠内核；会把模型不确定性与基础可靠性同时引入 |
| 允许 Recipe 任意 DAG 或表达式 | 可组合复杂任务 | 容易变成新的编程语言，增加权限逃逸、终止性与回归评估负担 |
| 第一版拆分大量微服务 | 独立伸缩与部署 | 初期没有负载证据，增加跨服务事务、运维和排障成本 |
| 第一版立即引入重型持久工作流平台 | 获得成熟的调度恢复机制 | 当前范围可用有限状态机验证；额外基础设施需由后续可靠性需求支持 |

数据库队列不是免费替代方案：团队仍需实现租约、幂等、重试、取消、检查点与发布一致性，并通过端到端故障场景证明其行为。若这些成本超过既有执行平台的运维成本，应重新评估，不坚持自研。

## 后果

- 正常任务不依赖模型，成本、权限和可重复执行边界较明确。
- 文件编辑不自动生效；显式校验、试跑和应用增加一步操作，但能阻止半写入配置、失效审批和未经审核的变更进入生产。
- 不维护前端与管理服务；操作者需要使用 CLI 和查看工件，权限依赖受控执行环境与文件边界，不能信任 YAML 自报身份。
- Recipe 对应一个可固定版本、可重放和可审核的优化对象。
- 系统能力上限由执行器决定；新协议、复杂版式或 OCR 需要明确开发工作。
- 人工配置与审核是首版必要成本；审过部分样本不代表整个来源已经证明正确。
- 将来增加 Agent 不需要重写数据管线，但仍需单独设计其身份、预算和只写候选权限。
- Recipe 回滚不能消除已发布错误数据，因此必须保留版本血缘和影响定位能力。

## 重新评估条件

出现首批来源确实需要的浏览器渲染、OCR 或授权协议时，先评估新增预置能力，而非开放任意代码。出现持续的大规模并发、复杂跨天等待或维护自研队列成本失控时，重新评估工作流执行平台。

允许模型辅助字段提取也应单独评估：它改变结果的可重复性、证据风险和成本，不应作为声明式 Recipe 的隐藏副作用加入。

## 验证与回退

决策的可用性以 [设计计划的验收章节](../plans/v1-information-pipeline.md#10-端到端失败方式与验收工件) 为依据。第一版可以暂停来源、撤销激活、回滚到仍被允许的 Recipe，并对受影响结果撤回或重处理。

此 ADR 保留被取代的提议而非实施结果。替代决策与尚未验证的集成风险见 ADR-0002；原方案没有生产实现需要迁移。

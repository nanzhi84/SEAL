# SEAL 数据库表结构

> 历史快照：2026-10-11，迁移仅覆盖到 `0006`，不是当前数据库结构。
> 本次从 Git 本地快照 `e7e21bd4533d3b0cbf6a09fe5bfb27620b81bc10` 恢复原稿；原工作区文件已缺失。
> 当前结构以 [迁移源码](../../src/seal/migrations) 和实际数据库为准。

基于演示库 `seal_demo_court`（PostgreSQL 17，schema `v1.2` + `seeded_discovery` 扩展，
迁移序列 `schema → 0002_runtime → 0003_records → 0004_discovery → 0005_recheck_plan →
0006_seeded_discovery`）的实际 `\d` 输出整理。完整 DDL 可由
`pg_dump -s -t 'seal_*' <dsn>` 重新生成。

19 张表 = 15 张 `seal_*` 业务表 + 4 张 `procrastinate_*` 任务队列表。

## 分层总览

```
合同层        seal_source ──< seal_binding >── seal_recipe_version
                  │               │
执行层            └──────< seal_run >──┐
                  │        │         │
                  ├─ seal_discovery（发现账本，每 URL 一行）
                  └─ seal_fetch_observation（每次抓取观察）
原文层        seal_document ──< seal_revision（修订链，不可变）
Record 管道   seal_record ──< seal_record_version（内容版本，不可变）
                  └──────< seal_record_result（处理结果，不可变）
                                └──< seal_record_emission（运行排放，不可变）
治理层        seal_decision（审计日志）/ seal_migration（迁移校验和）
```

正文原文不入库，按内容寻址存于 `SEAL_ARCHIVE/objects/<sha256前2位>/<完整哈希>`；
库内只存 `body_hash` / `snapshot_id` 指针。

**核心不变量**：`seal_recipe_version`、`seal_binding`、`seal_revision`、
`seal_record_version`、`seal_record_result`、`seal_record_emission`、`seal_result`、
`seal_decision` 均挂 `BEFORE DELETE OR UPDATE → seal_reject_mutation()` 触发器，
事实只追加、不修改。可变状态仅存在于调度/指针列（`seal_source.paused`、
`seal_record.latest_*` 等）。

## ① 合同层

### seal_source — Source 合同（每源一行）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | text PK | Source 标识（如 `demo_court_guiding_cases`） |
| `config` | jsonb | 整个 Source YAML 合同（hosts、路径前缀、预算、robots 等） |
| `binding_id` | text | 当前选用 Binding（可空） |
| `generation` | bigint | 合同代际，`source apply` 变更时递增 |
| `run_seq` / `write_seq` | bigint | 运行/写入序号（ fencing 用） |
| `paused` / `needs_repair` | bool | 调度开关 / 修复标记 |
| `cooldown_until` / `next_poll` | timestamptz | 退避与下次轮询时间 |

### seal_recipe_version — Recipe 版本（不可变）

`id`（内容哈希）PK、`manifest` jsonb（打包清单）、`created_at`。

### seal_binding — Source × Recipe × Params（不可变）

| 列 | 说明 |
|---|---|
| `id` / `fingerprint` | PK / 唯一约束（同一组合的重复创建幂等） |
| `source_id` → seal_source，`recipe_version` → seal_recipe_version | FK |
| `config` / `params` jsonb | 冻结的合同与参数快照 |

## ② 执行层

### seal_run — 一次运行

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | text PK | run_id |
| `source_id` / `binding_id` | FK | 所属合同与绑定 |
| `mode` | text | CHECK: `collect` / `recheck` / `replay` |
| `namespace` | text | `runtime` 或 `replay:<原run_id>`（隔离重放产物） |
| `generation` / `run_seq` | bigint | 与 source 一致的代际/序号（fencing） |
| `attempt_epoch` / `max_attempts` | int | 当前尝试轮次 / 上限（默认 3） |
| `deadline` | timestamptz | 运行截止时间 |
| `job_id` / `slot` | bigint / text | 队列作业 / 并发槽（`slot` 唯一） |
| `status` | text | `pending → complete / partial / failed / superseded` 等 |
| `seeds` / `replay_inputs` / `inputs` / `refs` | jsonb | 种子、重放输入、归档输入清单、引用 |
| `errors` | jsonb | 结束原因集合（如 `discovery_depth_exceeded`） |
| `report` | jsonb | 完整回执：stats、discovery 账本汇总、record_counts、scope_evidence、quality_status |
| `recheck_plan` | jsonb | 冻结的复采计划（CHECK 必须为 object 或 NULL） |

### seal_discovery — 发现账本（每个被发现的 URL 一行）

| 列 | 说明 |
|---|---|
| `run_id` / `source_id` | 所属运行与源 |
| `url` / `method` / `role` | 目标与角色（list/detail/robots/sitemap/attachment…） |
| `fingerprint` | 请求指纹（去重依据） |
| `parent_url` / `parent_snapshot_id` / `parent_observation_id` / `parent_discovery_id` | 发现来源（父页面证据链） |
| `transport` | CHECK: `discovery` / `retry` / `redirect` |
| `state` | CHECK: `discovered → requested → archived → parsed`，或 `failed` / `skipped` |
| `reason` | 拒绝/失败原因（`request_out_of_scope`、`request_excluded`、`discovery_depth_exceeded`、`robots_denied`、`duplicate_request` 等） |
| `depth` / `scope_decision` | 发现深度（≥0）/ 范围判定 |
| `duplicate_of` / `continued_by` | 去重与重定向续接指针 |
| `snapshot_id` / `observation_id` / `response_status` | 归档与观察结果 |
| `replayed` | 是否为重放消费 |
| `created_at / requested_at / archived_at / parsed_at` | 状态机时间戳 |

### seal_fetch_observation — 抓取观察（每次 HTTP 交换一行）

| 列 | 说明 |
|---|---|
| `request_id` | 唯一约束 |
| `request_key` / `method` / `url` / `final_url` | 请求身份与最终 URL（含重定向） |
| `status` / `error` | HTTP 状态或失败原因 |
| `snapshot_id` / `body_hash` | 归档指针与正文哈希 |
| `origin` | 默认 `network`（replay 消费时区分） |
| `parent_id` / `chain_id` | 重定向/辅助请求链 |
| `eligible` | 是否已被接受为有效输入（complete 接受时置真） |
| `requested_at / fetched_at / archived_at` | 时间线 |

## ③ 原文修订链（`generic_document.v1` 输出路径）

### seal_document — URL 身份文档

唯一约束 `(source_id, namespace, identity)`。`latest_revision` /
`latest_observation` / `current_result` 为当前指针；`next_check` /
`recheck_retry_at` / `recheck_failures` 驱动复查调度
（部分索引 `seal_document_due` 仅覆盖 `namespace='runtime'`）。

### seal_revision — 不可变修订链

`document_id` FK、`predecessor` 自引用成链、`body_hash` + `snapshot_id` +
`observation_id` 指向归档原文；唯一约束 `(document_id, observation_id)`
（同一观察不重复建修订）。

## ④ Record 管道（`record.v1` 输出路径）

### seal_record — 业务身份

唯一约束 `(source_id, namespace, record_type, record_key)`。
`latest_version` / `latest_result` 指针**只在 complete 运行的完成事务中推进**
（partial 不推进，因此不可复采）；`next_check` 驱动 recheck 计划；
`parent_request` 冻结父请求证据。

### seal_record_version — 不可变内容版本

| 列 | 说明 |
|---|---|
| `record_id` / `binding_id` / `run_id` | 归属 |
| `predecessor` | 版本链（自引用 FK） |
| `content_hash` | 内容哈希（recheck 判 `unchanged` 的依据） |
| `schema_version` / `data` | 如 `record.v1`；`data` 为结构化字段（title/body/date/blocks…） |
| `change_reason` | CHECK: `first_seen` / `source_updated` / `reprocessed` |

### seal_record_result — 不可变处理结果

唯一约束 `(processing_key, output_hash)`（幂等去重）。
`inputs`（snapshot/observation 血缘）、`candidate`（含 key_locator、字段
locator 证据）、`checks`（校验结果）、`content_hash` / `output_hash`。

### seal_record_emission — 运行排放事件（不可变）

把一次运行串到记录：`run_id` + `record_id` + `result_id` +
`observation_id` + `inputs`。审计“哪个运行、用哪份原文、产出了哪条记录的哪个结果”。

### seal_result — generic_document 路径的处理结果（不可变，逻辑删除用 `withdrawn` 标记）

结构同 `seal_record_result`，挂在 `document_id` 上。

## ⑤ 治理层

### seal_decision — 决策审计日志（不可变）

`kind`（当前 CHECK 仅 `control`）、`actor`、`payload` jsonb（如
`source_apply` 及配置哈希）、`idempotency_key` 唯一约束（可空，幂等重放保护）。

### seal_migration — 迁移校验和

`name` PK、`checksum`、`applied_at`。

## ⑥ 队列表（procrastinate_*）

`procrastinate_jobs` / `procrastinate_events` / `procrastinate_periodic_defers` /
`procrastinate_workers`：Procrastinate 队列库自建表，`--enqueue` 异步运行、
Worker 与定时调度使用；SEAL 业务逻辑不直接读写其结构。

## 关键设计语义（演示中已验证）

1. **不可变事实 + 可变指针**：版本、结果、排放、决策全部只追加；当前态靠
   `latest_*` 指针，且仅 complete 运行才推进 —— partial 运行的产物可见但不被接受。
2. **双输出路径**：`generic_document.v1` 走 document/revision/result；
   `record.v1` 走 record/record_version/record_result/emission。
3. **namespace 隔离**：replay 运行在 `replay:<run_id>` 命名空间重建记录，
   不污染 runtime 当前态（演示中 replay 复算出独立命名空间的 20 条记录）。
4. **发现账本即证据**：out_of_scope / excluded / depth_exceeded / robots 拒绝
   全部落 `seal_discovery`，覆盖缺口可审计而非静默丢弃。

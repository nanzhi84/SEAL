## 2. 冻结的 Record 与定位合同

`type=record` 包含 `record_type`、`record_key`、`schema_version`、类型化 JSON `data`、
可空 `detail_url`、每个 data 字段的 locator、`key_locator`、主 snapshot/observation、
补充输入，以及无详情时必需的 `frozen_parent_request={url,role,method:GET}`。
身份为 `(source_id, namespace, record_type, record_key)`；禁止列表下标或位置哈希作为键。
URL 键必须与实际归档响应及详情 URL 一致；JSON 整数键仅允许显式 `key_string` 转换。

一个响应可输出 0..N Record；一 Record 可引用多个输入，同一 snapshot 可被多个 Record
共享。每字段值必须从已归档输入复算，不接纳脱离原文的替代值。
JSON Pointer 保持数字、布尔、null、数组及对象类型，严格区别 false/0 和整数/浮点数，
拒绝非法转义、负数组下标、NaN/Infinity 和过深 JSON；旧字符串 locator 不变。
`record.v1` 是技术 JSON 合同，`schema_version` 为来源输出版本标识，不意味着业务准确性审核。

内容指纹只取 Record 类型、Schema 版本和有效 data；输入、页码、locator 位置、抓取时间
不进入业务指纹。列表重排只改变原文/定位证据，不改变各业务版本。
同一 Binding 的有效基线负责内容变化归因；换 Binding 的不同输出记为 reprocessed，
不能由新结果推断来源更新。原文 bytes hash 与业务内容变化分别记录。

stage 只写不可变处理结果与 emission；完成事务按键聚合。同键同内容去重并合并所有
输入血缘；同键异内容保留候选，整个键排除有效输出并使本轮 partial。
只有最终 complete 的完成事务推进 Record 当前指针；失败或 partial 不覆盖此前成功视图。
未观察旧 Record 一律 unknown，不自动删除，包括本轮零结果或声明范围不完整的情况。
写入继续遵守 Source → Run → Record 锁顺序及 generation/run_seq/attempt fencing。

## 3. Discovery、分页和资源边界

使用 Scrapy `request_scheduled` 信号在 Scheduler/原生 Dupefilter 之前记录发现，覆盖初始
种子及后续请求，保存实际 RequestFingerprinter 指纹、角色、父 URL/原文/Observation。
原生 `request_dropped` 标记去重；多个父页面可关联同一指纹，Discovery 不调度任何请求。
分页循环由原生去重终止，Recipe 仍可诊断不明确的分页或模板。

下载 Guard、归档、callback 和 item 校验关联 requested、archived、parsed、failed、skipped；
越界、预算、截止、下载失败、解析失败与去重分开计数。重试/跳转保留 transport 关系，
不能把已恢复的临时失败误判为未采资源。证据事件按 attempt 有上限；超过上限明确 partial。
发现数、实际网络交换、归档数、解析数、有效 Record 数分别报告，不据此宣称全站覆盖。

仍只允许冻结 GET/HEAD、无请求体，保留地址、敏感 URL/headers/body、响应大小及预算限制。
`host_path_scopes` 将每个主机与各自允许路径绑定；跨主机附件必须显式声明该映射，
不能扩大为多个主机共享路径的并集。静态 iframe 只跟进同主机公开 GET 子页。
普通展示资源不采集。业务 PDF/TXT/CSV 可归档及定位；不支持的 Excel/无文本层 PDF
保留归档、错误和未知范围，不引入 OCR 或浏览器。

## 4. Recipe、Recheck、Manifest 与查询

共享 helper 为普通 Python：HTML 正文、表格逐行、嵌套 JSON 列表、父来源 Request、
静态 iframe/附件及文本 PDF。不同 HTML 结构由 selector 参数或源级 Python 控制；
不引入 DSL、Registry、新 Frontier、消息队列、爬虫框架或工作流引擎。
既有 generic Recipe 和 Candidate 继续可用。

在线 Run Mode 只有 collect/recheck；Replay 仍为归档离线模式。
Recheck 选择 Record 的实际详情 URL，或冻结父列表/API 请求；相同父请求仅生成一个种子，
请求内部仍由 Scrapy 原生去重。周期任务的到期查询也包含 Record，Procrastinate 继续
负责持久调度。旧 V1.1 文档 Recheck 路径保留。

完成报告引用内容寻址、版本化 Manifest Artifact，包含研究 ID、Source、Binding、
RecipeVersion、Run、业务 scope、结果引用和资源统计。研究 ID 来自冻结配置，
不等同于 Source ID，不创建第二份人工状态表。`inspect research/source/run/manifest`
及 Export 可回查机器事实；Export 保留 documents，增量增加 records。
显式 Run 包括 partial 中有效输出；默认视图只选最近 complete 的成功输出，
已消失或未观察数据不自动抹除。所有出口 `quality_status=not_evaluated`。

## 2. 共享合同和模块边界

T1 修改 `crawl.py`、`discovery.py`、`archive.py`、`scope.py`，新增 `robots.py`、
seeded Recipe 和单个 `0006` 增量迁移。T2 修改 `helpers.py`、
`record_validation.py` 并新增 `fallback.py`。T3 修改 `runs.py`、`cli.py`、
`inspect.py`、`completion.py`。共享文件只由负责模块的一方编辑。

Recipe 参数承载 `max_depth`、`max_query_variants`、`exclude_patterns`、
`expand_homepage`、`discover_sitemaps` 和 `specific_rules`。请求预算、速率、
主机与路径继续由冻结 Source 配置限制。Seed 是探索入口，不等于全部业务范围。
跨域附件必须显式设置对应 `host_path_scopes`；iframe 不自动跨主机。

Request meta 使用 `seal_discovery_method` 和 `seal_depth`；父输入继续复用既有
`seal_parent_url`、Snapshot 和 Observation。Ledger 是证据层，不参与排队。
query 不排序、不重建原始 URL；fragment 不形成新资源；不采信 canonical 来自动扩大范围。
循环由原生 Dupefilter 终止，无界 query 受变体、深度、总请求和时间预算限制。

Specific 规则按 Recipe 参数声明顺序匹配；没有匹配才调用 Fallback。
Specific 已匹配但解析失败保留明确失败，不静默改用另一策略。
Record 自然键为真实响应 URL；字段和结构均由 Locator 从归档 bytes 复算。
无法可靠判断的日期为 null。导航、空白、登录、验证码及错误页不生成成功文档。
PDF、XLS 等复用已有附件解析；无法可靠解析的格式保存原文和失败原因。

## 3. 手动持久化采集与查询

`seal collect SOURCE [--binding BINDING] [--enqueue]` 调用现有 Run 路径；
旧 `seal run` 保持可用。`inspect run` 和回执提供当前 attempt 的计数与终止原因，
保留冻结报告；`inspect record ID` 查询业务身份和历史版本，
`inspect snapshot HASH` 核验原文引用及归档可读性。导出继续标记 `not_evaluated`。

重复 Collect 不增加相同业务内容版本；原文变化和结构化内容变化分别记录。
partial、failed、Replay 不提升在线有效视图。未观察到的历史 Record 保持 unknown。
重试仍最多三次 attempt 且总 deadline 不重置；不建立新状态机。

部署通过 `SEAL_DATABASE_URL` 和私有 `SEAL_ARCHIVE` 指定长期存储。
受管环境需要代理时显式设置 `SEAL_USE_ENV_PROXY=1`，继承平台代理与 CA，
不改变 Source / Recipe 安全范围，不清除平台代理。
演示数据库与归档不使用自动销毁的验收 Harness；跨进程查询和数据库重启后查询
用于证明当前 workspace 的留存。工作区生命周期与部署备份仍是运营边界。

确定性合同通过新单元测试、模拟 HTTP 站点和实际 PostgreSQL / CLI 测试证明。

dd-247、dd-357、dd-009。不得将 V1.2 的两页、单篇、固定查询或数量作为预期。

网络政策受阻也保留真实尝试和 Run，不把 proxy 错误页称为站点内容。

数量、失败和终止原因。队列耗尽不构成完整覆盖结论。

实际命令、结果和限制将在集成验证后补充本节。历史 PR #2、Issue #3 和历史工件
保持原状；新证据仅写入 `experiments/v1.3-acceptance/` 与本轮私有存储。

## 5. 迁移、兼容和回滚

仅追加 Discovery 元数据迁移；不改已应用 Schema 与 `0002`–`0005` 的 checksum，
不回填或修改历史结果。旧 Recipe、Source 默认配置和 URL 指纹保持兼容。
robots 在新 seeded 采集中必须启用；旧配置仍按旧版本合同执行。
新增 HTML locator 由新引擎注册，旧 locator 合同继续可读。

升级前停止旧 Worker、备份数据库与私有归档；升级后迁移、重新 pack Recipe 并创建
新 Binding。环境漂移校验禁止在已冻结 Binding 下原地替换引擎。
回滚时停止新 Worker，切回旧 checkout 和旧 Binding；增量列可保留供旧代码忽略。
新 locator 的结果由旧引擎读取可能 unsupported，须使用旧有效结果或保留新引擎查询。
不删除任何 Run、Record、Snapshot 或归档对象。

## C 两种场景分开
```flow LR
同一URL清单 -> Scrapy获取 & Firecrawl获取
Scrapy获取 -> 原生通用提取 & 相同PythonRecipe
Firecrawl获取 -> 原生通用提取 & 相同PythonRecipe
原生通用提取 -> 同一字段合同与独立标注
相同PythonRecipe -> 同一字段合同与独立标注
```
第一组比较低代码内容获取。
第二组隔离获取差异，不把共享 Recipe 算给某个框架。

## D 无效配对不进入分母
- 不用旧网络结果补齐当前实验。
- 不用 Parse 上传对比真实 URL Scrape。
- 不用合成页面替代候选网址。
- 不用 HTTP 200 代替正文正确。
- 不删除失败，也不把 UNKNOWN 当零分。
- 禁止因访问限制而切换引擎兜底。

## F 执行前需要确认
云 API 的一次调用不等于源站的一次请求。
当前不能验证云端全部子请求数量和间隔。
可选：批准客户端 HTTP/API 预算，云端内部记 UNKNOWN。
或者：用可计量出口的自托管环境实施严格控制。
不能暗中改变最初的请求限额口径。

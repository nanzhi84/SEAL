# PaddleOCR CPU 比较独立验收边界

业务目标：在同机 CPU、同输入、固定位置人工真值上比较简中、繁中、英语、越南语的速度/CER 帕累托前沿。

验收失败方式（在读取实现前记录）：

- 缺少任一语言或基线 tessdata_fast；Paddle 模型选择不能核对官方当前版本。
- 两个引擎使用不同图片、裁切、分辨率或真值；只有合成数据却推广到真实文档。
- 真值为空、位置未固定、OCR 输出被当作真值，或真值来源未声明人工转录。
- Unicode 未 NFC；中文空白影响 CER；英/越的连续空白未合并；CER 分母或编辑距离错误。
- OCR 异常、缺失、超时、非有限速度/CER 被作为有效点或进入前沿。
- Pareto 将相等点互相支配，或遗漏至少一个严格改善的条件。
- 热推理包含下载/初始化，冷启动和热推理的边界不清；不同引擎线程/设备不明确。
- 只报告一次时间却宣称稳定性能；重复次数或实际耗时缺失。
- 模型、输入、真值、源码无可校验 hash，配置未冻结，复跑命令缺失。
- 将仅识别/固定裁切结果宣传为整页检测识别性能；将微小样本宣传为语言总体结论。
- 验收或实验工件包含凭据、私人原文或未脱敏环境变量。

边界：空 OCR 文本仍可为有效错误率；CER 可以超过 1；相同 CER/耗时的点都属于前沿；不存在成功结果的模型不进入前沿；语言分别计算，不能以跨语言平均替代。

已确认业务口径：每语言 4 页、每页 3 个固定区域，完整页 OCR 后按几何位置提取。CER 按参考字符数加权（Σ编辑距离/Σ参考字符），速度为每页三次端到端（渲染、OCR、结构输出落盘）中位数之和。单线程 CPU。Paddle 常驻冷启动单列；Tesseract 逐页 CLI 启动纳入端到端耗时，报告须明确部署形态差异。

用户修订策略：先粗筛后前沿候选重复计时。screened 页面允许 1 次、replicated 页面至少 3 次；所有已评估成功点共同参与经验非支配重算，最终前沿必须 replicated。not_evaluated 与失败必须分开。不得将粗筛时间估计描述为三次重复中位数；需披露粗筛不确定性与未测配置范围。guard ratio 及邻居规则由实际 screening 配置核验。
